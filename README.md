# تطبيق المندوبين (بيع بالسيارة) — مربوط مع أودو

نظام متكامل لمندوبي شركة تجارة مواد غذائية:

| الجزء | المسار | التقنية |
|---|---|---|
| تطبيق أندرويد للمندوب | `android/` | Kotlin + Jetpack Compose، Room (قاعدة بيانات على الهاتف)، WorkManager |
| موديول أودو | `odoo/sales_rep_mobile/` | Odoo 19 (Community أو Enterprise) |

## ماذا يعمل النظام

- **يعمل بدون إنترنت**: كل العمليات (فاتورة، طلبية، تحصيل، زيارة، زبون جديد) تُحفظ على الهاتف فوراً، وتُرسل لأودو تلقائياً عند توفر الإنترنت. المزامنة مضمونة بدون تكرار حتى لو انقطع النت أثناء الإرسال.
- **المندوب ليس مستخدم أودو**: كل مندوب يُعرَّف في أودو كسجل «مندوب» مع رمز ورقم سري، ويدخل التطبيق بهما. لا يستهلك رخصة مستخدم. التطبيق يتصل بأودو عبر API خاص بالموديول (يمكن ربطه بمستخدم تكامل واحد من الإعدادات).
- **السيارة = مستودع**: لكل مندوب موقع مخزني داخلي (`Van R01`) يُنشأ تلقائياً. مخزون السيارة حقيقي في أودو.
- **تحميل السيارة = فاتورة على المندوب**: عند اعتماد التحميل في أودو:
  1. تحويل مخزني من المستودع الرئيسي ← سيارة المندوب.
  2. فاتورة مبيع (Customer Invoice) باسم المندوب كأنه زبون، بأسعار «قائمة أسعار التحميل».
  
  والتنزيل (إرجاع بضاعة للمستودع) = تحويل عكسي + إشعار دائن للمندوب.
- **البيع المباشر من السيارة**: المندوب يختار الزبون والمواد من مخزون سيارته، يحدد المدفوع (نقدي/آجل/جزئي)، وتُطبع الفاتورة فوراً على طابعة بلوتوث. في أودو تُسجل «فاتورة بيع من السيارة» وتنقص الكمية من موقع السيارة. لا تُنشأ فاتورة محاسبية ثانية للشركة لأن البضاعة محاسَب عليها المندوب عند التحميل (منعاً لتكرار الإيراد).
- **مرتجع من زبون** إلى السيارة، و**تحصيل** ذمم الزبائن مع إيصال قبض مطبوع.
- **طلبية من المستودع الرئيسي**: المندوب يرى مخزون المستودع الرئيسي ويأخذ طلبية من الزبون ← تُنشأ عرض سعر/أمر بيع (Sale Order) في أودو باسم الزبون، مع اسم المندوب. (اختياري: تأكيد تلقائي).
- **الزيارات بالـ GPS**:
  - تُفتح الزيارة تلقائياً عند اقتراب المندوب لمسافة **50 م** من الزبون (قابلة للتعديل من أودو).
  - تُغلق تلقائياً عند الابتعاد أكثر من 50 م + هامش 10 م (لمنع الفتح والإغلاق المتكرر بسبب تذبذب الـ GPS).
  - يلزم قراءتان متتاليتان دقيقتان (دقة أفضل من 40 م) للفتح أو الإغلاق، فلا تؤثر قفزة GPS واحدة.
  - المحلات المتجاورة: إذا صار زبون آخر أقرب بوضوح تُغلق الأولى وتُفتح الثانية.
  - فتح/إغلاق يدوي عند ضعف الـ GPS (يُعلَّم «يدوي» للمراجعة)، وسبب عدم البيع عند الإغلاق.
  - المندوب يقدر يحفظ موقع الزبون من مكانه («تعيين موقع الزبون هنا»).
- **الطباعة**: أي طابعة حرارية بلوتوث ESC/POS (58 أو 80 مم). النص العربي يُرسم كصورة لذلك يظهر صحيحاً على أي طابعة. يمكن أيضاً مشاركة الفاتورة كصورة (واتساب...).
- **واجهة بسيطة**: عربية بالكامل من اليمين لليسار، أزرار كبيرة، شاشة رئيسية فيها الزيارة الحالية وأهم العمليات.

## تنصيب موديول أودو

1. انسخ المجلد `odoo/sales_rep_mobile` إلى مجلد الإضافات (addons) في سيرفر أودو 19.
2. حدّث قائمة التطبيقات ثم نصّب **Van Sales** (`sales_rep_mobile`). يعتمد على: المبيعات، المخزون، المحاسبة.
3. **مهم**: الـ API يعمل بدون تسجيل دخول للمندوب، لذلك يجب أن يحدد السيرفر قاعدة البيانات تلقائياً:
   قاعدة بيانات واحدة، أو `dbfilter` في ملف إعدادات أودو (مثال: `dbfilter = ^mycompany$`).
4. من **Van Sales ← Configuration ← Settings**:
   - نصف قطر الزيارة (50 م)، هامش الخروج، أقل دقة GPS.
   - دفتر يومية فواتير التحميل (اختياري).
   - مستخدم التكامل (اختياري؛ مستخدم داخلي واحد يعمل الـ API باسمه).
5. من **Van Sales ← Reps & Customers ← Sales Reps** أنشئ المندوب:
   - الاسم، **الرمز** (مثل `R01`، يُستخدم للدخول وبادئة لأرقام الفواتير)، **الرقم السري** (4-8 أرقام).
   - المستودع الرئيسي، قائمة أسعار التحميل، قائمة أسعار الزبائن الافتراضية.
   - يُنشأ تلقائياً: شريك (زبون) باسم المندوب + موقع مخزني للسيارة.
6. اربط الزبائن بالمندوب من بطاقة الزبون (تبويب **Van Sales**): حقل المندوب، وإحداثيات الموقع إن وجدت.

### دورة العمل اليومية في أودو

| الخطوة | أين |
|---|---|
| المندوب يطلب تحميل من التطبيق | يظهر في **Van Loading** بحالة «Requested» |
| أمين المستودع يراجع الكميات ويضغط **Validate** | تُنقل البضاعة للسيارة + فاتورة على المندوب |
| المندوب يبيع ويحصّل | **Van Sales** و **Collections** (تقارير حسب المندوب/الزبون/اليوم) |
| الطلبيات | **Rep Orders** (أوامر بيع عادية) |
| الزيارات | **Visits** (المدة، يدوية/GPS، النتيجة: بيع/طلبية/تحصيل/بدون بيع) |
| المندوب يسلّم النقد | تسجيل دفعة عادية على شريك المندوب في المحاسبة ← ينقص رصيده |
| أخطاء المزامنة | **Configuration ← Sync Log** |

## بناء تطبيق الأندرويد (APK)

المتطلبات: Android Studio (أو JDK 17 + Android SDK 35).

```bash
cd android
./gradlew :core:test          # اختبارات منطق الـ GPS والحسابات والطباعة
./gradlew :app:assembleDebug  # الناتج: app/build/outputs/apk/debug/app-debug.apk
```

أو تلقائياً عبر GitHub Actions (`.github/workflows/android.yml`) عند كل push: يُرفع الـ APK كـ Artifact.

لنسخة Release موقّعة: أنشئ `android/keystore.properties` (لا يُرفع على git):

```properties
storeFile=release.jks
storePassword=...
keyAlias=rep
keyPassword=...
```

ثم `./gradlew :app:assembleRelease`.

### أول تشغيل على هاتف المندوب

1. ثبّت الـ APK، وادخل: عنوان سيرفر أودو (مثل `erp.company.com`)، رمز المندوب، الرقم السري. (أول دخول يحتاج إنترنت.)
2. اسمح بالموقع «أثناء استخدام التطبيق» والإشعارات. يظهر إشعار ثابت «تتبع الزيارات يعمل».
3. من الإعدادات: اقرن الطابعة من بلوتوث الهاتف ثم اخترها، وحدد عرض الورق.
4. يُنصح باستثناء التطبيق من «توفير البطارية» في إعدادات الهاتف حتى لا يوقف النظام تتبع الزيارات.

الهاتف مربوط بالمندوب: لتغيير الهاتف يضغط المدير **Reset Phone** في بطاقة المندوب.

## الاختبارات

- `android/core`: اختبارات وحدة لمحرك الزيارات (الفتح عند 50 م، الهامش، قفزات GPS، المحلات المتجاورة، الزيارة اليدوية)، الحسابات، الترقيم، ترميز الطباعة.
- `odoo/sales_rep_mobile/tests`: الدخول، التحميل (فاتورة + مخزون)، البيع من السيارة وعدم التكرار، زبون جديد بدون نت ← زيارة ← طلبية، عزل الأخطاء، المزامنة.
  تشغيل: `odoo -d test -i sales_rep_mobile --test-enable --test-tags /sales_rep_mobile --stop-after-init`

تفاصيل التصميم وبروتوكول المزامنة: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
